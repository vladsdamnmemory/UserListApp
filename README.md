### Как работает механизм SSR в Angular? Какие особенности нужно учитывать при разработке компонентов, которые будут рендериться на сервере?

Как и другие подобные фреймворки (Next.js, Nuxt) Angular Universal решает вопросы с SEO, ускоренной начальной загрузкой,
кэшированием и предоставлением лучшего пользовательского опыта.

#### Процесс рендеринга на сервере

1. При первом запросе браузер отправляет запрос на сервер.
2. Сервер выполняет рендеринг Angular-приложения с использованием Angular Universal. Он создает HTML-контент, который содержит все данные и структуру, необходимые для отображения страницы.
3. Полученный HTML отправляется обратно в браузер, и это сразу отображается пользователю.
4. Затем на клиенте происходит гидратация (hydration), когда клиентская версия Angular берет сгенерированный HTML и привязывает к нему интерактивность, выполняя все необходимые JavaScript-операции.

#### Особенности разработки компонентов для SSR

1. На сервере не доступен доступ к браузерным объектам, таким как window, document, localStorage, sessionStorage, и т. д.
2. На сервере компоненты Angular рендерятся до того, как сработает JavaScript-код. Поэтому если в constructor компонента используется логика, требующая доступа к браузерным объектам, это может вызвать ошибки. Лучше использовать методы жизненного цикла, такие как ngOnInit.
3. При работе с асинхронными данными желательно использовать TransferState, который позволяет передавать данные между сервером и клиентом, предотвращая повторные запросы на клиентской стороне.
4. На сервере нет реального DOM, поэтому любые манипуляции с ним приведут к ошибкам.
5. Многие сторонние библиотеки используют доступ к браузерным объектам, что может вызвать ошибки при рендеринге на сервере. В таких случаях стоит оборачивать использование таких библиотек в проверки на платформу (с помощью isPlatformBrowser или isPlatformServer).
6. Стили можно встроить в сгенерированный HTML или загружать их отдельно.
7. Можно использовать ленивую загрузку для частей приложения, которые загружаются только на клиенте.
8. И, конечно, один из основных плюсов SSR — это улучшение SEO, так как поисковые системы могут индексировать уже сгенерированный HTML.

### В чём разница между defer и lazy loading modules в Angular 17? Когда следует использовать каждый из этих подходов?

Использовать `defer` можно, если:

- Нужно отложить загрузку отдельных компонентов или инициализацию сервисов, которые не важны для первоначального рендеринга. Например, если компонент загружается поздно, когда пользователь взаимодействует с ним, но он не критичен для начальной загрузки страницы.

А вот `lazy loading` подходит, когда:

- Нужно разделить приложение на части и загружать их только тогда, когда они действительно нужны. Это полезно для больших приложений, где каждый модуль имеет множество зависимостей, и загрузка всех этих зависимостей сразу замедлит работу приложения. Идеально подходит для оптимизации загрузки страниц, особенно в случае с многостраничными приложениями.

### Опишите стратегии обработки ошибок при работе с HTTP запросами в Angular. Как организовать централизованную обработку ошибок и retry механизм?

- Оператор `catchError` позволяет ловить ошибки и обрабатывать их прямо внутри потока
- `Interceptor` перехватывает ошибки, позволяя обрабатывать их централизованно и выполнять повторные попытки, если необходимо
- Механизм повторных попыток `retry`. Позволяет автоматически повторить запросы при временных ошибках
- `retryWhen`, когда необходимо комбинировать обработку ошибок с механизми повторных попыток

### Как работает css z-index? Объясните понятие stacking context и известные вам  способы его создания. Как это влияет на отображение модальных окон в веб-приложении?

`z-index` в CSS используется для определения порядка наложения элементов на странице.

`z-index` применим только к элементам, которые позиционированы с помощью `position: relative`, `position: absolute`, `position: fixed` или `position: sticky`.

Он принимает числовые значения, где элементы с большим значением z-index будут находиться выше элементов с меньшим значением.

Stacking context — это концепция, описывающая, как элементы на веб-странице управляют своим порядком наложения. Каждый элемент может создать новый stacking context, что изменяет правила, по которым определяются отношения `z-index`. Каждый новый stacking context действует как независимый контейнер для своих дочерних элементов, и `z-index` дочерних элементов применяется только в пределах этого контекста, а не относительно других элементов на странице.

- Когда элемент имеет свойство `position: relative`, `position: absolute`, `position: fixed` или `position: sticky` и также имеет значение `z-index` отличное от `auto`, он создает новый stacking context:

```css
.modal {
  position: absolute;
  z-index: 1000; /* Новый stacking context */
}
```

- Когда элемент имеет значение `opacity` меньше 1 (например, `opacity: 0.5`), он создает новый stacking context.
- Элементы с `transform`, `filter`, `perspective` или другими подобными свойствами создают новый stacking context, даже если они не имеют z-index
- Свойство `will-change` также может создать новый stacking context

При работе с модальными окнами нужно учитывать, что элементы, создающие новый stacking context, могут изолировать модальное окно от остальной части страницы. Чаще всего используют `position: fixed` и правильный `z-index`, чтобы модальные окна отображались корректно.

### Как передать настройки приложения из переменных окружения в браузер?

В проекте Angular переменные окружения обычно задаются в файлах, таких как `src/environments/environment.ts` и `src/environments/environment.prod.ts`.

Эти переменные можно использовать в сервисах или компонентах Angular.

Иногда настройки приложения (например, ключи API или конфигурационные параметры) передаются в глобальный объект JavaScript с помощью атрибутов в index.html. Это делается до загрузки самого JavaScript приложения.

`localStorage` позволяет хранить данные в браузере на стороне клиента в виде ключ-значение.

`sessionStorage` аналогичен `localStorage`, но с важным отличием - данные сохраняются только в течение текущей сессии.

`Cookies` — это небольшие фрагменты данных, которые можно сохранять в браузере и отправлять на сервер с каждым запросом.

`IndexedDB` — это более сложная система хранения данных, которая позволяет хранить данные в виде объектов, включая большие объемы информации.
